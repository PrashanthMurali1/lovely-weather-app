# India Weather App Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an installable, offline-capable PWA with a FastAPI backend that searches Indian cities and shows current conditions, 48-hour and 7-day forecasts from ECMWF IFS via Open-Meteo, with server-side caching and quota protection.

**Architecture:** React SPA talks only to our FastAPI server. FastAPI normalizes Open-Meteo responses behind a `WeatherProvider` interface, caches them in SQLite (TTL, stale-while-error, daily budget guard), and sets HTTP cache headers. A Workbox service worker caches the app shell and last forecast on device.

**Tech Stack:** Python 3.11+, FastAPI, httpx, pydantic v2, sqlite3 (stdlib), pytest, pytest-asyncio, respx; React 18, Vite, TypeScript, vite-plugin-pwa, @tanstack/react-query, Vitest, Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-31-india-weather-phase1-design.md`

## Global Constraints

- Metric units only; times ISO 8601 with offset in `Asia/Kolkata`.
- Default model `ecmwf_ifs025`; `models` is allowlist-validated (unknown → 422).
- 48 hourly entries, 7 daily entries; hourly starts at the hour of `current.time`.
- Coordinates rounded to 2 decimals before cache lookup.
- Cache TTLs: forecast 1800 s, geocoding 2592000 s (30 days). Expired rows retained 86400 s for stale-while-error. Purge on startup and hourly.
- Daily upstream budget soft limit default 8000 (IST day), configurable.
- Upstream timeout 8 s; one retry on network error only; no retry on 4xx.
- Error shape: `{ "error": { "code": str, "message": str } }`. Codes: `invalid_request` (422), `upstream_unavailable` (502), `upstream_rate_limited` (503 + `Retry-After`).
- Headers: `/api/forecast` → `Cache-Control: public, max-age=300, stale-while-revalidate=600`; `/api/search` → `public, max-age=86400`.
- Search: `countryCode=IN`, max 8 results, query ≥ 2 chars.
- No accounts, no analytics; saved places in `localStorage` only; no IP geolocation.
- Attribution string comes from the API and is shown in the footer of every view.
- Accessibility: semantic HTML, 4.5:1 contrast, visible focus, `prefers-reduced-motion` respected.
- All settings come from environment variables (no hardcoded paths or origins).

## Review Focus

1. Open-Meteo returns `null` for `precipitation_probability` with IFS → schema allows `null`; UI shows "—", never "0%". (Task 4, Task 9)
2. `lat`/`lon` out of range or non-numeric → 422, not 500 or an upstream call. (Task 6)
3. Search query case/whitespace variants (`" CHENNAI "`) hit one cache key; 1-char query → 422. (Task 5, Task 6)
4. `localStorage` unavailable (private mode) or geolocation denied → app still renders with the default city. (Task 8, Task 9)
5. Upstream returns malformed/incomplete JSON → treated as upstream failure (stale served, else 502), never a 500 traceback. (Task 4, Task 5)

### Task 2: SQLite TTL cache

**Files:**
- Create: `backend/app/db.py`, `backend/app/cache.py`
- Test: `backend/tests/test_cache.py`

**Interfaces:**
- Produces:
  - `db.connect(path: str) -> sqlite3.Connection` (creates parent dir; `check_same_thread=False`; WAL mode).
  - `@dataclass CacheEntry(payload: dict, fetched_at: datetime, expires_at: datetime)` with property `is_fresh(now) -> bool`.
  - `class Cache(path: str, now: Callable[[], datetime] = utcnow)`:
    - `get(key: str) -> CacheEntry | None` — returns entry if present and within `expires_at + retention`; otherwise `None`. A corrupt/unreadable row returns `None`, never raises.
    - `set(key: str, payload: dict, ttl_seconds: int) -> None`
    - `purge(retention_seconds: int) -> int` — deletes rows whose `expires_at` is older than retention; returns count.
  - Table `cache(key TEXT PRIMARY KEY, payload TEXT, fetched_at TEXT, expires_at TEXT)`.

### Task 5: Cached service layer

**Files:**

- Test: `backend/tests/test_service.py`

**Interfaces:**
- Consumes: `WeatherProvider`, `Cache`, `Budget`, `Settings`, models, errors.
- Produces: `class WeatherService(provider, cache, budget, settings)`:
  - `async get_forecast(lat: float, lon: float, model: str = DEFAULT_MODEL) -> Forecast`
  - `async search(q: str) -> list[Place]`
  - `normalize_query(q: str) -> str` (module function: strip, collapse whitespace, casefold).
  - Key formats: `forecast:{model}:{lat:.2f}:{lon:.2f}`, `search:{normalized}`.
  - Behavior: fresh hit → return, no upstream. Expired or missing → if `budget.exhausted()` and a stale entry exists, return it with `stale=True`; else call provider under a per-key `asyncio.Lock`, `budget.increment()` per upstream call, store, return. Provider exception → stale entry with `stale=True` if any, else re-raise. Search results are never marked stale (just returned).
